# 택배 배송 게임 — 라이브 (호스팅 버전)

2인 실시간 동시진행 택배 배송 게임. Node.js `ws` 서버가 게임 상태를 소유하고,
접속한 두 브라우저에 WebSocket으로 실시간 동기화한다. 로그인 없이 링크(방 코드)만
있으면 누구나 들어올 수 있다.

## 구조

- `game-data.js` — 택배 종류/보상/층/방 번호 등 경제 상수. 서버와 빌드 스크립트가 공유하는 단일 소스.
- `game-room.js` — 방(room) 하나의 권위 있는 상태와 리듀서. 좌석 배정, 준비, 택배 확보, 엘리베이터 투표/이동, 채점.
- `server.js` — HTTP + WebSocket 서버. 방 코드 발급(`/` → `/?room=CODE` 리다이렉트), 클라이언트 정적 파일 서빙, 소켓 메시지 처리.
- `build_client.py` — `public/index.html`을 생성하는 빌드 스크립트. 퍼즐 이미지(base64)와 게임 상수를 `game-data.js`에서 읽어와 클라이언트에 그대로 반영한다. **`game-data.js`를 수정했다면 반드시 `python3 build_client.py`를 다시 실행해야 `public/index.html`에 반영된다.**
- `public/index.html` — 빌드 결과물 (커밋에 포함되어 배포됨).
- `test_hosted.js` — 실제 로컬 서버를 띄운 상태에서 두 플레이어를 시뮬레이션하는 Playwright 엔드투엔드 테스트.
- `screenshot.js` — 주요 화면 스크린샷을 찍는 스크립트 (디버깅/검수용).

## 로컬 실행

```bash
npm install
node server.js
```

기본 포트는 3000 (`PORT` 환경변수로 변경 가능). 브라우저에서 `http://localhost:3000/`을 열면
새 방 코드로 자동 리다이렉트된다.

## 클라이언트 재빌드가 필요한 경우

`game-data.js`(경제 상수)나 `build_client.py`(HTML/CSS/JS 템플릿)를 수정했다면:

```bash
python3 build_client.py
```

`game-room.js`나 `server.js`만 수정했다면 재빌드는 필요 없고, 서버만 재시작하면 된다.

## Render.com 배포

이 저장소는 `render.yaml`을 포함하고 있어 Render의 "Blueprint" 배포를 바로 쓸 수 있다.

1. https://render.com 에서 무료 계정을 만든다 (신용카드 불필요).
2. 대시보드에서 **New > Blueprint**를 선택하고 이 GitHub 저장소를 연결한다.
3. Render가 `render.yaml`을 읽어 Node 웹 서비스를 자동으로 구성한다. 그대로 **Apply**를 누르면 빌드가 시작된다.
4. 빌드가 끝나면 `https://<서비스이름>.onrender.com` 형태의 공개 URL이 생긴다. 이 링크를 그대로 열면 새 방 코드로 리다이렉트되고, 상대방에게는 그 이후의 링크(`?room=XXXX`가 붙은 링크)를 보내주면 같은 방으로 들어온다.

### 무료 플랜의 제약 (진행 전에 반드시 인지)

- **15분 동안 요청이 없으면 서버가 잠들고(spin down)**, 다음 요청이 오면 다시 깨어나는 데 **약 1분** 정도 걸린다. 두 사람이 게임을 시작하기 전에 링크를 한 번 열어서 "깨워두는" 것을 권장한다.
- 서버가 잠들었다 깨어나면 메모리에 있던 진행 중인 게임 상태(방, 점수 등)는 사라진다. 게임 도중에는 소켓이 계속 연결되어 있으므로 잠들지 않지만, 게임과 게임 사이에 오래 비워두면 이전 방 코드는 더 이상 유효하지 않다 — 새로 `/`에 접속해서 새 방을 만들면 된다.
- 이 프로젝트의 게임 상태는 애초에 파일이나 DB가 아니라 서버 메모리에만 있으므로, spin-down으로 인한 데이터 유실 자체는 구조적으로 "원래 그런 것"이지 버그가 아니다.

## 방 코드 / 좌석 구조

- `/`에 접속하면 4자리 방 코드로 자동 리다이렉트된다 (`0/O/1/I`처럼 헷갈리는 문자는 제외).
- 같은 방 링크로 들어온 두 사람이 각각 "플레이어 1"/"플레이어 2" 좌석을 고른다. 이미 다른 사람이 고른 좌석은 선택할 수 없다.
- 새로고침해도 좌석은 유지된다 (브라우저의 세션별 저장소에 저장된 고유 ID로 서버가 같은 사람인지 구분).
- 두 사람 모두 스페이스바를 누르면 자동으로 게임이 시작된다.
